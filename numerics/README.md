# Экспериментальные численные модули Rust

`csr` и `pcg` содержат разреженное умножение и Jacobi-PCG для вещественных SPD-систем. `jacobian` собирает полярный AC-якобиан; это не реализация полного расчёта режима и не основание применять PCG к общему несимметричному якобиану. Модули пока не подключены к Julia worker или браузеру.

## Якобиан: безопасный интерфейс

`JacobianPlan::new(n, slack, pv, pq, y_columns, y_rows)` получает каноническую CSC-структуру Y: индексы с нуля, отсортированные уникальные строки каждого столбца, смещения длиной n+1. PV/PQ должны без повторений покрывать все узлы, кроме slack. Координат, SQL и идентификаторов оборудования здесь нет — соответствие физических объектов узлам принадлежит вызывающему компилятору.

Порядок столбцов: углы PV/PQ, затем модули PV/PQ. Порядок строк: P для PV/PQ, Q для PQ, |V|² для PV. Это действующая расширенная постановка Enersy: J=−dF/dx. Напряжения, мощности и проводимости заданы в согласованных p.u., углы — радианы; базисы и физические модели выбираются снаружи.

`update(g, b, PolarState, demands, output)` принимает действительные/мнимые значения Y в исходном CSC-порядке и **рассчитанные** P/Q при переданном состоянии. Это не заданные паспортные мощности. ZIP-коэффициенты относятся к производным напряжение-зависимого потребления; несколько записей одного PQ-узла суммируются, привязка к PV/slack отклоняется.

План владеет неизменяемой структурой и позициями вкладов. Значения записываются в буфер вызывающей стороны длиной `row_indices().len()`. При успехе update не выделяет память; при ошибке буфер не использовать — часть значений могла быть записана. Нулевые позиции сохраняются, чтобы структура не менялась между итерациями. Смена топологии, нумерации или PV↔PQ требует нового плана; одинаковое количество узлов само по себе не разрешает переиспользование.

Само ядро использует безопасный Rust и стандартную библиотеку без дополнительных зависимостей. Экспериментальная C ABI-граница вынесена в отдельный feature `c-abi`; операции с указателями изолированы в `ffi.rs`, контракт — в `include/enersy_numerics.h`. Вызовы требуют живой доступной памяти без конкурентных записей; проверки указателей не создают песочницу. Адаптер WASM, отмена полного расчёта и привязка к Newton ещё требуют реализации.

Julia-адаптер расположен в `backend-julia/experimental/RustJacobian.jl`: `with_library`/`with_plan` владеют ресурсами в синхронной области одной задачи, освобождают их при исключениях и возвращают CSC с собственными Julia-массивами. Числовые handle не являются сохраняемыми ID или токенами доступа пользователя. Изменение структуры/PV/PQ требует нового плана; входы нельзя конкурентно изменять. Адаптер ещё не используется обычным HTTP-worker. [Контракт и проверенные измерения](../docs/site/development/native-jacobian.md).

## Проверка и измерения

Из корня репозитория:

```powershell
docker compose --profile numerics-check run --rm --build numerics-check
docker compose build julia-compute
docker compose --profile numerics-ffi-check run --rm --build numerics-ffi-check
./tests/integration/Profile-RustFfi.ps1 -OutputDirectory '.cache/rust-ffi-new'
./tests/integration/Profile-RustNewton.ps1 -Sizes 10000,100000 -Families ring,mesh -OutputDirectory '.cache/rust-newton-new'
docker build -f numerics/benchmark.Dockerfile -t enersy-rust-jacobian-profile numerics
./tests/integration/Profile-RustJacobian.ps1 -OutputDirectory '.cache/rust-jacobian-new'
```

Аналитическая двухузловая цепь проверяется с абсолютным допуском 10⁻¹²; центральные разности для PV/PQ, ZIP, несимметричной Y и отсутствующей диагонали — с h=10⁻⁶ и допуском 5·10⁻⁷. Файловый стенд сравнивает все значения Rust/Julia на больших матрицах и измеряет планирование, повторное обновление и полную пересборку. Его двоичный формат `ENJAC001`/`ENJOUT01` служит только локальной проверке, не является публичным протоколом моделей. Отдельный FFI-стенд измеряет реальный C-вызов и полный Julia-адаптер с проверками и копиями; это ещё не время полного решения Newton.

Обновление 2026-10-23: экспериментальные `solve_newton` и `solve_q_limits` используют Rust-Якобиан внутри обычного алгоритма Julia. План закрывается после каждого Newton-прохода; изменение активного PV/PQ-состава получает новый план. Линейная факторизация и поиск шага остаются Julia. Отдельный `rust_newton.jl` измеряет всё решение с созданием/закрытием плана; библиотека загружается вне таймера, первый вызов записывается отдельно. Стенд проверяет напряжения между backend, независимый баланс токов ветвей и совпадение с заданным корнем. Другой алгебраический корень явно отмечается `reference_root_matched=false`. Обычный HTTP-worker пока не подключён; версию/хеш native-библиотеки сохраняет экспериментальный отчёт, а не пользовательский снимок расчёта.
