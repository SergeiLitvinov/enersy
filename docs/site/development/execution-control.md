# Бюджет времени и отмена расчёта

Статус 2026-10-24: для Julia и Rust-Якобиана реализованы общий мягкий бюджет и программный токен отмены. Проверки выполняются между стадиями. Подтверждаемая отмена задания из интерфейса, жёсткий watchdog процесса и обработка OOM остаются в RUN-01/02 и PERF-04.

## Синхронный HTTP-контракт

Worker создаёт отдельный `CalculationControl` для каждого `/calculate`. По умолчанию бюджет — 20 000 мс, ниже 25-секундного ожидания Go-прокси. JSON может его сократить:

```json
{"executionOptions":{"max_time_ms":5000}}
```

Это дополнительное поле обычного запроса с components/connections, а не самостоятельный расчёт. Значение должно быть целым числом 1..20000; bool, null, строка, дробь, ноль, неизвестная опция или превышение максимума отклоняются с 400. В Go API используется query `maxTimeMs=5000`: как в проектных calculate/archive-calculation, так и в общем legacy calculate. Параметр попадает в точные байты входа и SHA-256 архива. Отсутствие query сохраняет прежние байты запроса; фактический стандартный бюджет записывается в ответе.

Бюджет отсчитывается монотонными наносекундами с создания контроля внутри worker. Он общий для подготовки DTO/сети, всех островов, всех PV↔PQ-проходов, Ньютона и финальной проверки перед публикацией. Он не начинается заново на каждой итерации. Чтение/декодирование HTTP-тела, создание контроля и передача ответа не входят в этот отсчёт.

| Событие | Ответ |
| --- | --- |
| Некорректный бюджет | 400, CONTRACT |
| Бюджет исчерпан в точке проверки | 504, EXECUTION / calculation_deadline_exceeded |
| Программная отмена в точке проверки | EXECUTION / calculation_cancelled; при HTTP-преобразовании 409 |

HTTP-пути для внешней отмены сейчас нет. Контроллер Go не сохраняет ответ worker с ошибкой как успешный архив. В успешном результате `solver.execution` содержит policy=`cooperative-checkpoints-v1`, `max_time_ms`, `native_calls_interruptible=false`, `disconnect_cancels=false`. Клиент проверяет подтверждение явно выбранного бюджета, в том числе относительно сохранённого входа архива. Старому архиву без execution нельзя приписывать новый бюджет.

## Программный доступ

```julia
using EnersyCompute
control = CalculationControl(max_time_ms=10_000)
task = @async calculate(components, connections; control)
# Из доверенного вызывающего кода, когда требуется остановка:
cancel_calculation!(control)
```

Это синхронизация внутри процесса, не идентификатор Run и не авторизация пользователя. Токен не переиспользуется и не сбрасывается. В прямом программном API можно задать другой представимый бюджет или `CalculationControl()` только с отменой без deadline; предел 20 секунд относится к HTTP. Вызов без контроля сохраняет прежний программный сценарий.

Точки проверки находятся до/после сборки сети и моделей, между островами и Q-проходами, на итерациях Ньютона, после мощностей/Якобиана/линейного решения, в пробах Armijo и перед публикацией. Кооперативная передача исполнения позволяет другой задаче установить атомарный флаг. Выход по отмене/сроку проходит обычные finally и освобождает native-планы.

## Граница гарантий

Текущий C-вызов Rust, UMFPACK и отдельная длинная стадия сборки не прерываются посередине. Мягкий бюджет может быть превышен до следующей проверки; 20 секунд не являются жёсткой верхней границей wall time. Не используются `Task.throwto`, освобождение памяти из другой задачи или принудительное прерывание FFI с живыми указателями. Жёсткие ограничения требуют отдельного процесса задания и watchdog.

Разрыв HTTP-соединения или закрытие окна не устанавливает этот флаг. Go прекращает ожидание по своему контексту, но это не подтверждение остановки worker. Поэтому интерфейс не показывает неподтверждённую кнопку «Отменено». Для пользовательской отмены ещё нужны авторизованный Run, передача команды, подтверждение конечного состояния и при необходимости остановка изолированного процесса.

## Подтверждённые проверки

35 новых проверок Julia используют аналитическую двухузловую цепь, монотонные часы с детерминированным истечением/переполнением UInt64, отмену из другой задачи и остановку после настоящей сборки Якобиана. Проверено, что закончившийся после deadline остров не публикуется как частичный успех. Настоящий HTTP проверяет 400/504 и восстановление следующего запроса. Полный обычный набор Julia также прошёл; известная проблема выбора корня радиальной сети 100k этим не исправлена.

18 новых native-проверок останавливают расчёт после настоящего FFI-обновления, проверяют нулевое число оставшихся handle и следующий успешный расчёт. Вместе с прежними проверками — 230 native/HTTP/численных утверждений. Физические PV→PQ и PQ→PV-эталоны пройдены с включённым контролем.

Полный набор frontend: 471 проверка прошла, одна HTTP-проверка пропущена в этом окружении. В браузере на одноразовом Docker-стенде проверены реальный Rust-расчёт с бюджетом 1 мс (диагностика истечения срока), блокировка запуска при значении 0 и следующий успешный запуск с бюджетом 10 секунд. Трёхузловая схема сошлась за четыре итерации; результат показал подтверждённые worker движок и бюджет. Это проверка восстановления после ошибки, а не доказательство жёсткого ограничения времени.

На одноразовом Go→native HTTP→PostgreSQL стенде подтверждены сохранение выбранного бюджета во входе и результате, побайтная сохранность архива и неизменность при последующем редактировании схемы. Отдельный явно обозначенный HTTP failure fixture проверяет, что 504 не создаёт новый архив; он не является физическим эталоном или имитацией успешного решателя. Основная база не использовалась.

```powershell
docker compose build julia-compute
docker run --rm --network none enersy-julia-compute julia --project=. test/runtests.jl
docker compose --profile numerics-ffi-check run --rm --build numerics-ffi-check
docker compose -f tests/integration/native-compose.yml run --rm archive-check
docker compose -f tests/integration/native-compose.yml down
```

Для одноразового стенда нужен заранее заполненный локальный кэш Go-модулей, как в CI. [Native worker](./native-jacobian.md), [пользовательское руководство](../guide/calculation.md).

## Холодный HTTP-запуск и условия приёмки — 2026-10-26 {#cold-http-acceptance}

При проверке упаковки [лицензий Rust](./asset-provenance.md#rust-license-inventory) одновременно запущенные WASM-компиляция и native HTTP-приёмка дали сбой первого native-тестового запроса: ответ не содержал `solver`/`topology`. В первоначальном тесте HTTP-статус и тело ошибки не были записаны, поэтому утверждать конкретный код или причину этого отказа нельзя. Тест теперь явно проверяет 200 и выводит диагностическое тело при ошибке до чтения полей результата.

Отдельный холодный запрос на той же проектной 12-узловой схеме с лимитами контейнера 2 CPU/2 GiB вернул 200 и `success=true` за 19,412 секунды. Последовательный полный native-набор без параллельной сборки прошёл 236 проверок, включая 40 HTTP-утверждений; бюджет HTTP остался 20 секунд, численные допуски не менялись. Native-библиотека до/после упаковки уведомлений совпала побайтово. Первый неуспешный прогон не выдаётся за успешный и не доказывает математическую регрессию либо установленную причину сбоя.

Одна успешная холодная попытка не гарантирует укладывание в бюджет на любом CPU или при конкурирующей нагрузке. JIT, ожидание CPU и сборка моделей требуют отдельных холодных измерений PERF-01. Readiness сейчас подтверждает загрузку модуля, а не полную предварительную компиляцию всех моделей; отдельный запуск задания, политика инициализации и жёсткий watchdog остаются в плане. Увеличение лимита не подменяет эти проверки.
