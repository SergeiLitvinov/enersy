# Минорные обновления PostgreSQL

Основной Compose и одноразовые стенды закреплены на PostgreSQL 15.19 по digest. Основной сервер и проверки восстановления используют Debian, интеграционные Go/worker-стенды — Alpine. Вариант образа сохраняется при физической замене сервера; путь данных — `/var/lib/postgresql/data`.

По [документации PostgreSQL](https://www.postgresql.org/docs/15/upgrading.html) минорные версии одной major-ветки сохраняют формат данных: сервер останавливают и заменяют исполняемые файлы. Перед обновлением нужно проверить [release notes 15.19](https://www.postgresql.org/docs/15/release-15-19.html): расширения, индексы и конфигурация могут требовать отдельных действий. Этот процесс относится к 15.18 → 15.19; major-upgrade требует отдельной приёмки.

## Автоматическая приёмка

```powershell
# Чистый сервер текущей закреплённой версии: backup и restore.
./scripts/database/Test-DatabaseBackup.ps1

# Предыдущая minor-версия: физическая замена на том же тестовом томе,
# затем восстановление дампа старой версии в отдельную БД.
./scripts/database/Test-DatabaseBackup.ps1 `
  -Image 'postgres:15@sha256:c2ca90969ca293925ab474466e837689cc712321afdd9e4640bd0cf942fdca3a' `
  -UpgradeImage 'postgres:15.19@sha256:baa22e6286bf832cb147b8bb5aa9d8bc999846d69c21d11bf63f58fbeed1fa48'
```

Сценарий проверяет фактические версии бинарных файлов и допускает только повышение minor в одной major-ветке. Для физического обновления создаётся собственный том с уникальным именем и меткой владения. Старый сервер останавливается штатно; новый запускается с тем же томом. Рабочие контейнеры и данные приложения не используются, сеть отключена. При завершении удаляются только созданные сценарием контейнер и проверенный по метке тестовый том; evidence остаётся в `.cache`.

Приёмка сравнивает полный SQL, кириллицу, параметры, ограничения целостности, неизменяемость версий исследования, точные байты и SHA-256, значения последовательностей. Существующая цель восстановления и повреждённый dump отклоняются. Отдельная копия восстановленной БД проверяет обнаружение изменённой координаты при прежнем количестве строк; она отделена от основного сравнения, поскольку изменение объекта увеличивает его ревизию. Обе проверки добавлены в CI. В [удалённом CI 284fa01](documentation.md#remote-ci-284fa01) backup/restore текущей версии прошёл, а шаг обновления остановился на разборе версии при загрузке образа. Исправленный разбор и полный сценарий обновления повторно проверены локально; удалённая приёмка исправления ещё предстоит.

`Test-PostgresVersionOutput.ps1` отдельно проверяет получение ровно одной полной строки версии из вывода Docker, включая сообщения загрузки образа. Код завершения Docker проверяется независимо; диагностика без версии, несколько строк и неверный формат не принимаются за подтверждение версии.

## Проверка конкретной резервной копии

```powershell
# Отчёты и дампы хранить локально; в Git и web-документацию их не включать.
New-Item -ItemType Directory -Force .backups | Out-Null
./scripts/database/Get-DatabaseDataFingerprint.ps1 -OutputFile .backups/before.json
$backup = ./scripts/database/Backup-EnersyDatabase.ps1
./scripts/database/Test-DatabaseRestore.ps1 `
  -Backup $backup -ExpectedFingerprint .backups/before.json `
  -OutputFile .backups/restore-check.json
```

Для сопоставления с дампом запись должна быть остановлена либо отдельно подтверждено отсутствие изменений до/после backup. `Get-DatabaseDataFingerprint.ps1` читает обычные и partitioned-таблицы выбранной схемы и состояния `last_value`/`is_called` последовательностей. Несуществующая схема отклоняется, а не трактуется как пустая. Строки хешируются внутри PostgreSQL, промежуточные SHA-256 сортируются; отчёт содержит имена отношений, количество строк и контрольные суммы, без исходных значений. Для таблиц используется read-only repeatable-read transaction с таймаутами. Последовательности не подчиняются MVCC, поэтому при активной записи это не единый транзакционный снимок всего состояния. Эти суммы подтверждают содержимое выбранных отношений; схема, расширения, роли кластера и локали проверяются отдельно. Контрольные суммы не являются анонимизацией данных.

`Test-DatabaseRestore.ps1` создаёт отдельный PostgreSQL без сети, портов и рабочих томов, проверяет manifest/SHA-256 дампа и восстанавливает его в новую БД. При переданном `ExpectedFingerprint` сверяется содержимое всех перечисленных отношений; несовпадение завершает проверку ошибкой. Без него отчёт указывает `fingerprintCompared=false`, `dataMatch=null`. Роли, ownership и privileges не включены в существующий логический backup; политика их восстановления остаётся отдельной. Основной сервер этим сценарием не изменяется.

## Проверка 2026-10-25

На `linux/amd64` прошли физическая замена 15.18 → 15.19 на тестовом томе и восстановление дампа 15.18, а также backup/restore на чистой Debian 15.19. Go vet/build и 91 верхнеуровневый PostgreSQL-тест с детектором гонок прошли на чистой Alpine 15.19; три отдельных сценария worker/профилирования пропущены в этом Go-стенде. Отдельно прошли два сценария расчётных архивов и замороженного исследования с реальным Julia/Rust worker на PostgreSQL 15.19. Проверки неверного ожидаемого fingerprint и отсутствующей схемы подтвердили отказ вместо ложного подтверждения сверки.

Рабочая БД также обновлена с сохранением исходного тома. До замены проверено: только `plpgsql`, нет logical slots и preload libraries, нет расхождений локалей. Реальная резервная копия восстановлена на Debian 15.19 без сети: совпали 27 таблиц и 19 последовательностей. Перед заменой API остановлен, повторно сверены данные с проверенным дампом и подтверждено отсутствие других клиентов БД. После замены совпали все 46 fingerprints и контрольная сумма 13 ролей PostgreSQL, включая системные; расхождений collation versions нет. API прошёл readiness, каталог сохранил 604 совпавшие записи и прежнюю контрольную сумму. Пользовательские имена, владельцы legacy-данных и роли участников проектов не менялись.

Уточнение удалённой приёмки: [CI 68a52c9](https://github.com/SergeiLitvinov/enersy/actions/runs/40776064078) полностью прошёл, включая оба сценария backup/restore и физическую замену PostgreSQL 15.18 → 15.19. Тем самым исправление разбора версии при pull подтверждено на удалённом Linux amd64 runner; ARM64-приёмка этих шагов ещё предстоит в новой матрице Go.
