# Профиль чтения расчётного снимка

## Область измерения

`TestCalculationSnapshotProfilePostgres` измеряет настоящий `readCalculationInput` с PostgreSQL: транзакция, три запроса, получение строк, декодирование JSON параметров и сборка Go DTO. Время подготовки fixture, `ANALYZE`, GC перед выборкой и проверка результата исключены. Измеряется первый запрос и 20 последующих; p50/p95 — nearest-rank по этим 20 запросам. Все исходные выборки сохранены в [JSON-отчёте](/reports/storage-snapshot-2026-10-08.json).

Генератор детерминированный, без случайного seed: ID 1..N, N шин с `voltage_nom=110 kV`, координата X равна ID, N−1 связей `right → left` между соседями. Проверяются каждый ID, координаты, тип, параметр и обе стороны каждой связи; быстрый частичный или неверный результат не принимается. Это синтетический граф хранения, а не физически питаемая сеть или независимый численный эталон. Число объектов не равно числу электрических узлов после компиляции.

В замер не входят HTTP, сериализация ответа, браузер, Julia, JIT, компиляция топологии и решение режима. PostgreSQL/RSS, пик памяти и конкурентные пользователи пока не измеряются. `runtime.MemStats.TotalAlloc` показывает суммарные выделения Go за чтение, включая временные объекты, а не размер живого снимка или RAM. В процесс не запускаются другие тесты; фоновые выделения runtime/драйвера могут входить в счётчик.

## Повторение через Docker

Из корня репозитория:

```powershell
docker compose -f tests/integration/revision-compose.yml --profile snapshot-profile run --rm snapshot-profile-check
docker compose -f tests/integration/revision-compose.yml --profile snapshot-profile down
```

Профиль поднимает временную PostgreSQL без пользовательского тома; каждый размер получает отдельную SQL-схему с актуальными миграциями. Репозиторий монтируется read-only, только `.cache` и кэши Go доступны для записи. Итог — `.cache/snapshot-profile.json`; принимать его только при успешном завершении команды, поскольку файл предыдущего запуска может оставаться после ошибки. Образ Go получает зависимости через отдельную сеть `web`. Host-компилятор не требуется.

Обычные Go-тесты пропускают этот дорогой профиль без `ENERSY_SNAPSHOT_PROFILE_OUTPUT`. Он не является CI-бюджетом скорости: CI проверяет корректность и планы индексов, а время на общих runners не сопоставимо с этим стендом. Следующие измерения: графы с несколькими схемами и большим количеством параметров, HTTP/JSON, конкуренция, память БД и UI.
