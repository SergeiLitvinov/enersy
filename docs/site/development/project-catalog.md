## Данные и границы проверки

Паспорт — данные изделия, а не пакет уравнений. Документ формата 1 содержит код типа, название, производителя, источник, декларацию лицензии и карту параметров `{value, unit}`. Значения сохраняются строками, единицы — явно. Источник и лицензия обязательны, но их наличие не означает проверки происхождения или прав; это декларация автора.

Сервер проверяет UTF-8, размеры строк, отсутствие NUL, непустые название/источник/лицензию и хотя бы один параметр. Код и ключи должны существовать в текущем шаблоне типа. Единицы должны буквально совпадать с шаблоном: преобразования `MW` ↔ `МВт` и SI/p.u. здесь не выполняются. Числа — конечные десятичные строки с необязательным показателем степени; boolean — `true`/`false`. Defaults не добавляются. Неизвестный ключ/тип значения/единица отклоняется.

Это структурная проверка **черновика**, а не доказательство достаточности данных для AC/RMS/EMT, достоверности заводских значений или физических диапазонов. Частичный набор параметров допустим в draft. Статусы reviewed/published и проверка обязательных параметров конкретной математической модели — последующие этапы.

Каждая версия имеет отдельный строковый BIGINT ID, проект, автора, время, целую ревизию и SHA-256 канонического JSON. Байты документа неизменяемы; UPDATE запрещён триггером. Новая версия ссылается на предшественника того же проекта и типа; ревизия увеличивается на 1. Один предшественник имеет одного преемника. Устаревшая ветка получает 409, существующая версия не переписывается. Для независимого изделия создаётся корневая версия без предшественника.

Идентификаторы этого каталога **не являются** `equipmentModelId` общего справочника. Для них используется отдельная привязка `projectPassportVersionId`.

## Привязка экземпляра: серверный этап 2026-10-21

Приватный `POST /api/projects/{project}/schemes/{scheme}/components` принимает необязательный `projectPassportVersionId` — строковый положительный BIGINT. Вместе с ним `equipmentModelId` должен отсутствовать или быть `null`. Общий legacy-маршрут проектный паспорт не принимает. В диалоге добавления источник выбирается отдельно от общего справочника.

Сервер в одной транзакции проверяет права, принадлежность версии проекту и типу, целостность документа и совместимость ключей/единиц с текущим шаблоном. Затем копирует строковые значения и применяет явно переданные `params` экземпляра. Неизвестные ключи и некорректные числовые/boolean значения при создании отклоняются; defaults не добавляются. Изменившаяся единица старого паспорта блокирует создание. Это структурная проверка draft, а не допуск к инженерному расчёту.

Ответ создания и приватный снимок схемы возвращают `projectPassportVersionId` строкой либо `null`. Парсер редактора сохраняет ссылку без преобразования в Number. Новая версия паспорта не меняет ссылку или параметры существующего объекта. Последующее редактирование параметров меняет экземпляр; исходный документ остаётся неизменным. Отдельная история overrides и перенос паспортного происхождения в архив расчёта ещё не реализованы.

Миграция `20261021001_component_passport_binding` добавляет FK и запрещает два источника паспорта, изменение привязки, несовместимый тип и перенос связанного объекта/схемы в другой проект. При удалении схемы её объекты удаляются обычным каскадом. Down работает только при отсутствии привязок; используемое происхождение автоматически не удаляется.

Проверено на одноразовой PostgreSQL в Docker: копирование `10.00`, отдельные overrides `12.00`, новая версия `25.00` без изменения старых объектов, повторное чтение схемы, редактирование экземпляра без изменения паспорта, запрет чужого проекта и типа, несовместимых единиц и обхода SQL-ограничений; откат пустой миграции и отказ отката используемой. Полный Go-набор с race и `go vet` прошёл. Frontend: typecheck/lint, 336 тестов прошли, один HTTP-тест пропущен без своего профиля. Это результаты серверного этапа до подключения UI; актуальная приёмка и поставка описаны ниже.

## HTTP API

Маршруты защищены существующей cookie-сессией, точным Origin для записи и `Cache-Control: no-store`.

| Маршрут | Метод | Результат |
| --- | --- | --- |
| `/api/projects/{project}/passports` | GET | `{items, nextAfterId?}`, `limit=1..100`, `afterId` по возрастанию ID |
| `/api/projects/{project}/passports/{version}` | GET | Одна неизменяемая версия |
| `/api/projects/{project}/passports` | POST | Создать корень или следующую версию; ответ 201 с сохранённой версией |

POST требует один UUID в `Idempotency-Key` и `Content-Type: application/json`. Пример тела (тестовые данные, не заводской паспорт):

```json
{
  "predecessorId": null,
  "document": {
    "formatVersion": 1,
    "componentTypeCode": "generator",
    "name": "Пользовательский источник",
    "manufacturer": "",
    "source": "Параметры учебного примера",
    "license": "Авторская декларация условий использования",
    "parameters": { "p": { "value": "10.00", "unit": "МВт" } }
  }
}
```

Для следующей версии указывают ID предшественника строкой. Повтор того же UUID с тем же документом и предшественником возвращает прежний ID, включая одновременные запросы. Изменение содержимого под тем же UUID даёт 409. После потери ответа повторяют исходную команду с исходным UUID, а не создают новый. Повтор также проверяет текущие права и состояние сессии.

Наблюдатель читает, owner/admin/editor читают и создают версии. Чужой проект/версия, отозванная сессия или запись наблюдателем не раскрывают документ. Права блокируются и перепроверяются в транзакции; квота и команды сериализуются на проекте. Действующая версия доступна действующим участникам проекта, а не только её автору.

Лимиты: 128 параметров в документе, 1000 символов на значение, 64 КиБ канонического документа, 70 КиБ HTTP-запроса, 1000 версий и 16 МиБ документов на проект. Квота не мешает повторному получению уже сохранённой команды. Переполнение квоты/конфликт версии или команды — 409, неверные поля/единицы — 400, чрезмерное HTTP-тело — 413. Удаление проекта удаляет его версии. Отдельных UPDATE/DELETE паспортов и публикации в общий каталог сейчас нет.

Миграция `20261020001_project_passports` добавляет отдельную таблицу, FK проекта/автора/типа/предшественника, уникальные ключи команды и преемника, ограничения размера и триггер неизменяемости. Down удаляет проектные паспорта и не является штатным откатом пользовательских данных.

HTTP-проверки включают неверный JSON, неизвестные поля, отсутствующий UUID, media type и ограничение размера, в том числе длинный хвост пробелов. Численные эталоны не запускались: физические уравнения не менялись.

UI проверен Docker typecheck/lint/build и полным frontend-набором: 335 passed, один отдельный HTTP-тест пропущен без своего профиля. Новые 15 проверок охватывают контракт ответов, чужой проект, изменённое подтверждение, отмену, роль наблюдателя, поздний ответ после смены проекта, клонирование, двойной submit, повтор исходного UUID после неопределённого отказа, локальную ошибку и несовместимые единицы. Переданные значения копируются в подготовленную попытку; повторный запрос не берёт заново отредактированную форму. SHA-256 ответа проверяется на формат, не пересчитывается клиентом; сервер проверяет сохранённые байты.

Браузерная приёмка на одноразовом Docker API/PostgreSQL: владелец создал паспорт с `power_nom=10.00 МВА`, `voltage_nom=10.5 кВ`; следующая версия сохранила `25.00 МВА`, первая осталась `10.00`. Клон стал отдельным корнем с ревизией 1. После reload все три записи доступны. Пользователь явно разрешил роль viewer второму синтетическому аккаунту в этом тестовом проекте: в браузере он прочитал вторую версию без кнопок записи, а выход очистил приватную страницу. Временный стенд удалён. Автоматические HTTP-проверки прав относятся к предыдущему серверному этапу; новые frontend mock-тесты не заменяют их.

Журнал не доказывает выполнение создания и не повторяет его автоматически: после потери подтверждения требуется явная сверка схемы.

Исправлено растягивание радиокнопок стилями страницы проектов. Численное ядро не менялось; расчёт в этом сценарии не запускался.

## Происхождение в архиве расчёта — 2026-10-21

Архивируемый запуск захватывает происхождение в той же PostgreSQL Repeatable Read транзакции, что параметры и связи. Для каждого объекта сохраняются ID, ревизия, имя и вид источника: без привязки, общий legacy-каталог или версия паспорта проекта. Для проектного паспорта копируются ID версии, её ревизия, SHA-256 и документ с исходными значениями, единицами, источником и условиями использования. Текущий каталог при последующем открытии не читается.

Эти сведения хранятся отдельно от точного запроса решателю: worker их не получает, SHA-256 его входа сохраняет прежний смысл. Миграция `20261021002_calculation_provenance` добавляет необязательные BYTEA и SHA-256. Старые архивы остаются без происхождения; оно не восстанавливается из нынешней схемы. Новые данные имеют предел 8 МиБ и учитываются в общей квоте архива 64 МиБ. До обращения к worker слишком большой снимок происхождения отклоняется с 413. Down разрешён только при отсутствии сохранённого происхождения.

Метаданные архива содержат необязательные `provenanceSha256` и `provenanceBytes`. `GET /api/projects/{project}/calculation-archives/{archive}/provenance` возвращает точные JSON-байты формата 1 с ETag; для старой записи без происхождения — 404. Доступ соответствует остальным ресурсам архива. Сервер проверяет контрольные суммы; клиент сверяет ID архива, ETag, размер и соответствие оборудования входному снимку. SHA-256 клиентом повторно не вычисляется.

В просмотре исходных данных выбранного объекта показан сохранённый паспорт. Строки значений и обозначения единиц сравниваются отдельно: одинаковые `10` с единицами МВт и Вт не получают общего статуса совпадения с паспортом. Разное написание MW/МВт отмечается как различие обозначений, а не физическая несовместимость. Если единица в снимке отсутствует, это указано явно; она не заимствуется из паспорта. Это сравнение сохранённых строк, не пересчёт величин или история редактирования. Для legacy-каталога сохранён только ID: исходная версия общего паспорта неизвестна. Полнота данных для физической модели и история overrides остаются отдельными задачами.

Проверены Docker-сборки API/frontend, frontend typecheck/lint и 348 тестов (один отдельный HTTP-тест пропущен без своего профиля), Go с race на настоящей PostgreSQL, сохранность после изменения паспорта/экземпляра и удаления схемы, отказ выдачи повреждённого происхождения, up/down пустой миграции и отказ down с данными, запрет чтения из чужого проекта. Приёмка с настоящим Julia worker сохранила запрос 543 байта и результат 5172 байта; невязки тестовой сети: P около −1.75e−14 МВт, Q около −5.91e−14 Мвар. Это проверка хранения существующего результата, не новый независимый физический эталон. В браузере через computer-use открыт настоящий архив схемы «источник — линия — нагрузка»: исходные `p=9 МВт` и параметр экземпляра `p=10 МВт` показаны раздельно.
