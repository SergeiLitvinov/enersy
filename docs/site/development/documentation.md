# Документация и CI

## Единый процесс

Руководство находится в `docs/site/guide`, пояснения разработчикам — в `docs/site/development`. Основные правила, анализ и план сохраняются в `docs/CODING_RULES.md`, `docs/PROJECT_REVIEW.md` и `TODO.md`: сайт копирует их автоматически, вручную дублировать не нужно.

Установите Node.js 24 и pnpm 11.19.0, затем из корня проекта:

```sh
pnpm install --frozen-lockfile
pnpm docs:dev
```

Перед отправкой изменений:

```sh
pnpm docs:build
pnpm docs:preview
```

Сборка выполняет тесты генератора, создаёт справочник, запускает TypeDoc и проверяет внутренние ссылки VitePress. Итог — автономный статический сайт `docs/site/.vitepress/dist`, без сервера БД и вычислительного worker. Поиск работает локально в браузере.

## Автогенерация кода

TypeDoc строит семантический справочник экспортированных функций и типов `frontend/src/api/ees-api.ts`. Он не описывает всё приложение.

`scripts/docs/generate.mjs` индексирует объявления TypeScript, Go, Julia, Rust и SQL, сохраняет исходники с комментариями/docstrings и номера строк. Индекс текстовый: не обещает разрешение типов или перегрузок. Пути и содержимое берутся из текущего дерева; выдуманных ссылок на ещё не опубликованный commit нет.

Генератор читает только перечисленные каталоги кода и четыре канонических документа, включая отчёт проверки реализации. `.env`, БД, `node_modules`, `target` и сторонние символы в сайт не включаются. Сгенерированные каталоги не коммитятся; при следующем запуске они полностью обновляются, поэтому удалённые объявления не остаются в справочнике.

## Docker и автоматическая проверка

```sh
docker compose --profile docs up -d --build docs
```

При изменении исходников повторите сборку. Сервис документации использует отдельный порт 4173 и не изменяет БД. В CI сборка проверяется и сохраняется как скачиваемый артефакт. Автоматическое публичное размещение не включено: статический каталог можно публиковать отдельно после настройки выбранного хостинга.

## Правила изменения

Меняя поведение, обновляйте соответствующее руководство и API-комментарии. Формулы сопровождайте единицами и областью применимости. Проверяйте сайт в браузере: переходы, поиск, тему и узкий экран. Не исправляйте файлы в `generated` или `public/api` вручную.
