# Реестр дефектов

Начат 2026-10-03 в FIX-01. Реестр дополняется по мере проверки; он не является полным аудитом всех моделей. Первопричины F01–F04 подтверждены статическим чтением прежнего кода, F05–F07 дополнительно воспроизведены до исправления. Исправленное поведение проверено реально запущенными регрессиями.

| ID | Дефект и минимальное воспроизведение | Исправление и доказательство |
| --- | --- | --- |
| F01 | `SolverOptions(Inf, 10)` обходил keyword-проверку через автоматически созданный типизированный конструктор. При бесконечном допуске метод мог принимать произвольную конечную невязку. | Проверка в inner constructor; оба способа создания отклоняют NaN/Inf/неположительный допуск, неверный/слишком большой лимит. Julia testset `Power flow setup cannot bypass validation`. |
| F02 | Типизированный `PowerFlowSetup` обходил внешнюю проверку размеров; PV/PQ могли повторять slack, пересекаться, пропускать узлы или ссылаться за пределы матрицы. | Единственный проверяемый конструктор: полный раздел узлов, согласованные размеры, конечные мощности, положительные конечные напряжения. Ошибка `inconsistent_setup` до индексирования. |
| F03 | В одноузловом режиме без неизвестных `Y=[NaN]` либо переполнение `S` возвращались без проверки конечности мощностей. | Проверки Y и вычисленного S, без исключения для slack-only. Независимый шунтовый эталон: V=1.2 p.u., Y=0.5−j0.25 p.u.; P=0.72, Q=0.36 p.u., абсолютный допуск 1e-12. NaN/Inf и конечный Y, вызывающий переполнение, отклоняются. |
| F04 | Изменение переданных массивов после создания постановки меняло задачу; изменение индексов внутри публичного setup могло приводить к BoundsError. | Массивы копируются при создании; постановка повторно валидируется на входе solver. Проверено изменение исходных PV/P и mutation собственного PV. |
| F05 | `generator.r=-0.1`, `transmission_line.r0=-0.1` или `g0=-0.001` принимались пассивными моделями; все три входа реально воспроизведены расчётом без исключения до исправления. Отрицательные R/G создают искусственную активную выдачу. | Проверки неотрицательных R/G до сборки Y. 6 проверок входов и точных CONTRACT/invalid_parameter в `Passive equipment rejects artificial energy generation`. Нулевые R/G разрешены; знак реактивных параметров этим изменением не ограничивается. |
| F06 | `transmission_line.circuits=1e100` проходил проверку целочисленности Float64 и давал необработанный `InexactError` при `Int(circuits)`; реально воспроизведено до исправления. | Общий проверяемый `as_int`; CONTRACT/out_of_range с именем поля вместо внутреннего исключения. 2 проверки. |
| F07 | Явная ЭДС `e=0` или `e=-1` молча заменялась `voltage_nom` в `source_spec`; четыре комбинации slack/PV реально воспроизведены до исправления как успешный расчёт изменённой физической задачи. | Проверка заданной ЭДС на положительность/конечность; fallback только при её отсутствии. 16 проверок двух источников и двух значений через функцию расчёта и реальный HTTP: CONTRACT/invalid_parameter, HTTP 400 с component/field. |

| F08 | После первоначального нарушения двух Q-границ монотонный PV→PQ оставлял источник 2001 ограниченным, хотя ограничение 2002 позволяло ему снова регулировать ЭДС. Схема `q_release_network` воспроизвела семь падений относительно независимого конечного PV/PQ-эталона. | Возврат PQ→PV по условиям Q/напряжения, восстановление исходной постановки, события и явные отказы при цикле/бюджете. 28 проверок эталона/потоков/баланса/реального HTTP, 2 аналитические проверки отказов. |

Проверено Docker Julia: 969 проверок в testsets плюс самостоятельная проверка переменной базиса. Набор включает 40 проверок конструкторов, 38 независимых многоузловых эталонов, 24 проверки компиляции нагруженного трансформатора, 8 проверок пассивных параметров, 325 проверок многоисточниковых схем/ЭДС/HTTP, 140 проверок профиля Q-границ внутренней ЭДС, 35 проверок разреженного ядра и 290 проверок независимых питаемых островов. [Методика](numerical-validation.md), [стенд CSC](sparse-compute.md). Это не подтверждает полные терминальные Q-ограничения машин, динамику или масштаб полного приложения.

Открытые направления FIX-01: PV/Q-ограничения, собственные/системные базисы и единицы паспортов, острова и трансформаторы; в редакторе смена схемы во время записи, connect/move/delete/reload и сетевые отказы. Каждый закрываемый дефект получает минимальный пример и отдельное доказательство.
