# Расчёт и ошибки

## Сходимость и допустимость

В результатах есть отдельный раздел «Режимные ограничения». Сообщение «ограничения не заданы» означает, что допустимость по ним не проверялась. У старого архива оценка может отсутствовать. Сходимость сама по себе не подтверждает допустимость, единственность или устойчивость режима; номинальное напряжение не назначает допустимый диапазон автоматически.

Чтобы задать границы напряжения, сначала выполните расчёт без них. Закройте результат, нажмите «Границы», выберите оборудование и терминал, заполните минимум и максимум в кВ и примените к следующему расчёту. После нового запуска появятся оценка и таблица проверок. В проектном режиме применённые границы сохраняются в архиве расчёта; при его открытии сверяются с сохранённым входом.

После изменения состава или связей схемы прежние границы требуют пересмотра: очистите их явно и выполните базовый расчёт заново. Перемещение и поворот рисунка границы не сбрасывают. Пока настройки открытого редактора не сохраняются между перезагрузками и не являются отдельным версионированным исследованием. [Область проверки и контракт](../development/operating-limits.md).

## Выбор вычислительного движка

Поле «Лимит, мс» задаёт бюджет от 1 до 20 000 миллисекунд, по умолчанию 20 000. Он общий для всех этапов текущего синхронного запроса. После истечения сервис возвращает ошибку вместо частичного результата; успешный архив не создаётся. В результате и архиве отображается подтверждённый сервисом бюджет. Пустое или неверное поле блокирует запуск.

Остановка проверяется между этапами: отдельный нативный вызов может завершиться позднее заданного срока. Закрытие окна не является подтверждённой отменой worker. Для больших длительных расчётов ещё разрабатывается контур асинхронных заданий. [Точные гарантии и API управления](../development/execution-control.md).

В панели расчёта выберите «Вычислительный движок», затем модель, метод и «Рассчитать». Список загружается из подключённого вычислительного сервиса. В обычной поставке доступна Julia. Если оператор подключил опциональный Rust-worker, появляется «Julia + Rust · экспериментальный»: Rust собирает Якобиан, остальные стадии выполняются общим алгоритмом Julia.

Если выбранный движок больше недоступен, он остаётся в поле с этой пометкой, а запуск блокируется. Нажмите «Обновить список движков» и явно выберите доступный вариант. При ошибке загрузки списка запуск также недоступен. Автоматического переключения между движками нет; выбор не сохраняется между отдельными редакторами проектов/пользователей.

В окне результата раздел «Вычислительный движок» показывает реально использованную реализацию. В «Версии и контрольные суммы» доступны версии и SHA-256 кода Rust/Julia/адаптера, переданные сервисом. При выборе движка клиент требует его подтверждения в ответе. Архив открывается со своими сведениями и сверяется с сохранённым выбором; старый результат без этих данных помечается «движок не указан». Данные не восстанавливаются из текущих настроек сервера.

Наличие Rust не означает гарантированного ускорения каждого расчёта или подтверждённой применимости всех моделей. [Измерения, ограничения и настройка опционального worker](../development/native-jacobian.md).

## Профиль нагрузки PQ и ZIP

Выберите нагрузку на схеме и откройте «Инспектор → Параметры». В форме «Мощность и зависимость от напряжения» доступны PQ и ZIP. PQ сохраняет постоянную мощность. ZIP задаёт независимые доли постоянного сопротивления Z, модуля тока I и мощности P для активной и реактивной мощности.

Задайте полные трёхфазные P в МВт и Q в Мвар, номинальное линейное действующее напряжение в кВ и все шесть долей ZIP. Каждая доля лежит в [0,1], каждая колонка даёт сумму 1 с допуском 10⁻¹². Десятичный разделитель — точка. Доли автоматически не заполняются и не нормализуются. Если Q отсутствует, текущая модель явно принимает 0 Мвар; для ZIP номинальное напряжение обязательно. Положительные мощности означают потребление, отрицательные — выдачу.

Нажмите «Применить профиль»: весь набор записывается одной операцией с проверкой ревизии. До применения расчёт использует сохранённые значения, а черновик формы ещё не входит в журнал правок. «Вернуть сохранённый» отменяет черновик формы. Применение PQ очищает доли ZIP. Прочие поля объекта сохраняются отдельно при выходе из поля. При неподтверждённом сохранении правки остаются в журнале; расчёт заблокирован до сверки с сервером. Если сохранённые значения изменились во время редактирования формы, автоматической перезаписи нет.

В результатах раскройте «Нагрузки»: здесь указаны ID оборудования и расчётного узла, профиль, фактическое напряжение, Uном и фактические/номинальные P/Q. Номинальные мощности ZIP относятся к Uном; при другом напряжении потребление отличается. Для PQ мощности постоянны, Uном в этой модели результата не используется. Отрицательная Q допустима и означает выдачу реактивной мощности. Таблица показывает по 50 нагрузок с переключением страниц. Старый архив без этих сведений открывается с пометкой об их отсутствии; значения не восстанавливаются из текущей схемы.

ZIP здесь — статическая симметричная AC-модель. Она не описывает пуск двигателя, частотную зависимость, отключение по снижению напряжения и переходные процессы. Формулы и проверенные примеры — [численная проверка](../development/numerical-validation.md#zip-нагрузки-2026-10-21).

## Фазные данные линии в симметричном расчёте

π-модель линии использует явно заданные r0/x0, g0/b0, длину и число цепей. Собственные фазные R/X и взаимные R/X здесь служат вспомогательными данными; полноценная фазная матрица не собирается, параметры последовательностей из неё не выводятся.

NaN, бесконечность или неверный текст в любом известном фазном поле блокируют расчёт с указанием линии и ключа; отрицательное собственное R также недопустимо. Пустое необязательное поле считается отсутствующим. Различия диагональных значений с r0/x0 и ненулевые взаимные параметры показываются в предупреждениях результата. Порог сверки диагоналей — 1% от выбранного r0/x0; при нуле эталона видно любое ненулевое отличие. Это служебная проверка согласованности ввода, а не нормативный допуск и не доказательство симметрии сети. Проверяйте применимость самостоятельных r0/x0 перед использованием симметричного результата.

## Двухобмоточный трансформатор

Выберите трансформатор и откройте раздел модели в свойствах. Схема показывает последовательное сопротивление КЗ, идеальную трансформацию 1:k и ветвь намагничивания на ВН. «Развернуть модель» открывает увеличенное представление с уравнениями. T1 соответствует ВН, T2 — НН; вращение значка не меняет назначение сторон.

Таблица перечисляет фактические значения объекта и контракт ядра: Sном в МВА, Uвн/Uнн в кВ, потери КЗ/холостого хода в **МВт**, u_kz/i_xx в процентах. Не переносите потери в кВт без пересчёта. Отсутствие обязательного параметра блокирует расчёт; ненулевые потери холостого хода требуют достаточного i_xx. Если p_xx/i_xx не заданы, ядро принимает нули и сообщает, что намагничивание не учитывается; форма не записывает эти значения в паспорт.

В параметрах доступен `phase_shift_deg` от −180° до 180°. Положительный угол означает опережение НН относительно ВН **на холостом ходу**; под нагрузкой углы также зависят от падения напряжения. При отсутствии поля принимается 0° с записью допущения. Фазосдвиг задаётся явно, а не выводится из группы соединения. В потоках результата показан сохранённый φ НН−ВН; старый архив без этого поля показывает «Не передано».

Это симметричная AC-модель. РПН, нейтраль, нулевая последовательность и динамика здесь не рассчитываются. Просмотр не выбирает другое замещение и не создаёт привязку модели исследования.

## Номинал конденсатора и реактора

`q_nom` — полная трёхфазная реактивная мощность при собственном `voltage_nom` шунта, а не при максимальном номинале других устройств узла. Напряжение задаётся в линейных действующих кВ. При фактическом U реактивная мощность меняется как `(U/Uном)²`: конденсатор выдаёт, реактор потребляет. Разные шунты одного узла могут иметь разные паспортные номиналы; их проводимости рассчитываются отдельно.

Если собственное напряжение не задано, модель может взять известный номинал узла и записывает это в допущения результата. При отсутствии обоих значений положительная `q_nom` блокирует расчёт. Явная `q_nom=0` даёт нулевой вклад; ноль вместо номинального напряжения недопустим. Пустая строка в необязательном поле означает отсутствие данных, а не физическое нулевое напряжение. Основание проверки — [NUM-SHUNT-01](../development/defects.md#num-shunt-01-номинал-шунта-подменялся-номиналом-узла-2026-10-21).

Пока уровни напряжения не выделены в самостоятельные данные сети, компилятор дополнительно сверяет номиналы всех устройств одного узла: разница максимального и минимального, делённая на максимальный, не должна превышать 10%. Проверка не зависит от ID или порядка объектов. Это текущее ограничение совместимости исходных данных, а не допустимое отклонение рабочего напряжения по ГОСТ/IEC и не замена паспортных ограничений оборудования.

Пассивные модели линии и сопротивления источника отклоняют отрицательные
активные сопротивления; линия также отклоняет отрицательную активную
проводимость. Число параллельных цепей должно быть положительным целым в
поддерживаемом диапазоне. Ошибка содержит компонент и параметр: исправьте
исходные данные перед повторным расчётом.

Заданная ЭДС генератора `e` должна быть положительной и конечной. Нулевая или
отрицательная ЭДС блокирует расчёт; она не заменяется номинальным напряжением.
Если ЭДС отсутствует, применение `voltage_nom` явно отражается в допущениях.
Каждый питаемый остров рассчитывается отдельно. При нескольких источниках
в острове выберите ровно один балансирующий генератор параметром `is_slack=true`;
остальные задают P и модуль внутренней ЭДС. Единственный источник острова
может быть выбран автоматически. После соединения островов пересмотрите выбор
балансирующего источника: два slack в одной связной сети отклоняются.
Остров без источника пока прекращает весь расчёт; обесточенный режим не подставляется.

В окне результатов для нескольких островов показаны их состав по числу узлов,
балансирующие источники, итерации и невязки. Каждый остров имеет свой опорный
угол, поэтому углы разных несвязанных островов нельзя использовать для оценки
синхронизма. Общий лимит итераций распространяется на все острова и Q-проходы.

В экспериментальном API-профиле источника можно задать пару
`q_min_emf_mvar` / `q_max_emf_mvar` — границы Q внутренней ЭДС в Мвар.
При нарушении PV переходит в PQ; Q фиксируется, модуль ЭДС становится результатом,
событие отображается в предупреждениях. Эти границы не относятся к терминалу
машины. Нарушение объявленных границ балансирующего источника прекращает расчёт.
Если после других переключений источник может снова поддерживать уставку,
он возвращается PQ→PV; возврат также отражается в предупреждениях.
Цикл переключений или исчерпание бюджета прекращает расчёт с диагностикой.
Смена балансирующего источника пока не поддержана.

Окно результатов отдельно показывает мощности внутренней ЭДС, выдачу на внешних
выводах и ΔP/ΔQ внутреннего сопротивления каждого генератора. Положительная
мощность означает выдачу, отрицательная — потребление. Разность мощностей ЭДС
и выводов равна потерям внутренней ветви; это не описание всех потерь машины.
Режим Slack/PV/PQ, объявленный диапазон Q и состояние «На границе», «В диапазоне»
или «Не заданы» относятся к внутренней ЭДС. Терминальные Q-ограничения пока не
поддержаны. В старых архивах отсутствующие поля показаны как «Не передано» и не
вычисляются заново. На узком экране таблица прокручивается по горизонтали.

## Поддержанный сценарий

Панель получает доступные сочетания модели и метода из Julia через API. Сейчас выполняется только `three-phase / newton-raphson`: **симметричный AC-режим в полярных координатах**. Название группы историческое; это не расчёт трёх независимых фаз. Статус — **экспериментальный**.

Прямой метод режима, фазные координаты и симметричные составляющие отклоняются. Раздел [план работ](/generated/todo) описывает будущее развитие, а не доступные функции.

Кнопка «Возможности и ограничения расчёта» открывает перечень сочетаний модели и решателя с причинами их недоступности. Данные получены из ядра, а не из статического списка интерфейса.

## Перед запуском

Задайте параметры с единицами из шаблона: напряжение — кВ, активная мощность — МВт, реактивная — Мвар, сопротивление — Ом; для линии удельные параметры умножаются на длину. Реальные значения уточняйте в коде модели и шаблоне параметров, особенно проводимости линии. Калькулятор не заменяет проверку паспортов.

Соедините источники и потребителей через поддержанные ветви. Нужные параметры должны быть конечными числами. Неподдержанный аппарат или несовместимые уровни напряжения приводят к отказу. Наличие графического символа не означает наличие математической модели.

Ядро проверяет состав Slack/PV/PQ: каждый узел относится ровно к одной группе. Напряжения должны быть положительными и конечными, мощности, углы и проводимости — конечными. Проверка действует также при прямом вызове численного модуля разработчиком. Положительный конечный допуск и число итераций обязательны; даже одноузловая задача не возвращает успех при переполнении вычисленной мощности.

Нажмите «Рассчитать». Запрос синхронный: пауза, продолжение, checkpoint и управление длительным заданием ещё отсутствуют. API ограничивает ожидание worker 25 секундами. Отмена HTTP-запроса не гарантирует немедленного прерывания численной функции Julia.

## Результат

Напряжения узлов возвращаются в кВ, углы — в градусах; расчёт внутри ведётся в p.u. на общей базовой мощности и напряжении. В результате также возвращаются ветви, потери, баланс, число итераций, статус и предупреждения. Текущий интерфейс отображает только часть этих данных; полный JSON доступен через API.

Диалог результата показывает напряжения и углы с единицами, число узлов, итерации, время и предупреждения о границах применимости. Данные проходят проверку типов и конечности чисел перед отображением. При ошибке постоянное сообщение остаётся под панелью расчёта; уточнение содержит идентификатор проблемного объекта, если ядро его сообщает.

Источник представляется ЭДС за сопротивлением с внутренним slack/PV-узлом, а не полноценной динамической моделью машины. Поддержан описанный выше профиль Q-границ внутренней ЭДС; терминальные ограничения машин пока не применяются. Плотные матрицы ограничивают масштаб; пригодность для крупных сетей ещё не измерена.

## Если расчёт не удался

| Диагностика | Действие |
| --- | --- |
| Неподдержанный метод или элемент | Выберите доступный сценарий; соответствующая функция остаётся в плане |
| Недостающий / недопустимый параметр | Проверьте объект, единицу и поле, указанные в сообщении |
| Остров без источника | Проверьте порты, провода и состояние аппаратов |
| Вырожденная матрица | Проверьте топологию и физическую постановку; не заменяйте ошибку нулевыми результатами |
| Несходимость | Проверьте нагрузку и параметры; увеличение числа итераций само по себе не доказывает существование решения |
| API / worker недоступен | Проверьте готовность контейнеров и журнал |
