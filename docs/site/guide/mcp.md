# Работа со схемой через MCP

MCP — дополнительный способ подключить внешний агент к тому же проекту, который открыт в редакторе. Обычная программа запускается без него и без LLM. Встроенного чата и исполнителя агентных ходов пока нет.

## Возможности первой версии

| Инструмент | Действие |
| --- | --- |
| `scheme.read.v1` | Текущий снимок выбранной схемы |
| `component.create.v1` | Создание оборудования с исходным UUID и ожидаемой ревизией; повтор возвращает постоянную квитанцию |

По умолчанию доступно только чтение. Создание требует одновременно явного `ENERSY_MCP_ALLOW_WRITE=true` и действующих прав записи в проекте. Список перечитывается перед каждым вызовом. Ни просмотрщик, ни ранее полученный список инструментов не обходят серверные права. Расчёты, редактирование связей, удаление, SQL и команды устройствам через мост пока недоступны.

Проект и схема закрепляются при запуске; инструмент не принимает чужой scope, токен или автора в аргументах. Мост запоминает точные account/session ID и передаёт их как ожидания API. Отзыв сессии прекращает доступ. Для переключения проекта или сессии нужно запустить другой экземпляр.

## Подключение в Docker

Сначала запустите обычное приложение с настроенной приватной авторизацией. `AUTH_ORIGIN` должен точно совпадать с настройкой API. Если он пустой, приватный API намеренно недоступен; MCP не включает авторизацию за пользователя.

Создайте отдельную сессию для агента через штатный вход `/api/auth/login`. Сохраните **только значение её session cookie** в локальном файле `.secrets/mcp-session`, доступном вашему пользователю. Не кладите токен в аргументы инструмента, настройки LLM, URL, Git или общие журналы. Каталог `.secrets/` исключён из Git и контекста Docker-сборки. Мост читает файл при запуске; для смены сессии требуется перезапуск.

Пример переменных окружения PowerShell для локального HTTP-стенда с уже включённой авторизацией:

```powershell
$env:AUTH_ORIGIN = 'http://localhost'
$env:ENERSY_MCP_PROJECT_ID = '1'
$env:ENERSY_MCP_SCHEME_ID = '1'
$env:ENERSY_MCP_SESSION_PATH = 'C:/project/enersy/.secrets/mcp-session'
$env:ENERSY_MCP_COOKIE_NAME = 'enersy_session'
$env:ENERSY_MCP_ALLOW_WRITE = 'false'
docker compose --profile mcp build mcp
```

У локального HTTP API должна быть явно настроена `AUTH_COOKIE_SECURE=false`; для защищённой поставки оставьте штатную secure cookie `__Host-enersy_session`. Изменение переменной в текущей оболочке само по себе не перенастраивает уже запущенный API.

В клиенте с поддержкой запуска stdio MCP задайте исполняемую программу `docker`, рабочий каталог `C:/project/enersy` и аргументы:

```json
["compose", "--profile", "mcp", "run", "--rm", "--no-deps", "-T", "mcp"]
```

Переменные выше передайте окружением запуска клиента. Сборку и запуск зависимостей выполните заранее. Один процесс обслуживает одно подключение; сетевой MCP-порт не открывается. stdout занят только JSON-RPC, диагностика идёт в stderr. Закрытие клиента завершает мост и не останавливает приложение.

## Повтор и ограничения

### Явные единицы при создании

`component.create.v1` принимает `equipment.parameterUnitDeclaration` формата v1. Для каждой объявленной единицы передайте исходное значение в `equipment.params` той же команды. Например, фрагмент оборудования:

```json
{
  "params": { "voltage_nom": "110000.0000" },
  "parameterUnitDeclaration": {
    "formatVersion": 1,
    "units": { "voltage_nom": "В" }
  }
}
```

Это только фрагмент: остальные поля, новый UUID команды и наблюдённая ревизия берутся из актуального контекста. Значение сохраняется точно; единица не пересчитывает число. Для безразмерной величины используйте `1`. Нельзя объявить единицу каталожного параметра, не передав его значение явно. Единицы остальных полей копируются из выбранной версии проектного паспорта, если они в ней указаны; для старого общего справочника не выводятся из сегодняшнего шаблона.

Форма декларации и пределы опубликованы в каталоге инструментов; соответствие ключей значениям и полный контракт обозначений повторно проверяет API. Мост проверяет, что квитанция вернула точные запрошенные значения и единицы. Отсутствующая декларация, другая единица или округлённое значение не считаются подтверждением. Квитанция уже удалённого объекта может быть исторически корректной: затем обязательно прочитайте текущую схему.

Мост не повторяет POST с телом автоматически после потери ответа. Явный повтор использует исходные UUID, ревизию, значения **и единицы**; изменение одной единицы при том же UUID — другое намерение и отклоняется. Это фиксация данных экземпляра, а не подтверждение достаточности исходных данных или инженерного расчёта.

Для записи сначала прочитайте текущую схему. Возьмите существующий typeId и явные параметры оборудования; мост не подставляет физические значения. При неопределённом исходе сохраните тот же commandId, исходный expectedTopologyRevision и payload. Повтор с новым UUID может создать второй объект. После квитанции прочитайте схему заново: квитанция подтверждает принятую команду, а не текущее существование объекта.

Отмена MCP-запроса прерывает ожидание и HTTP-запрос. Она не обещает отмену уже принятой транзакции. Неуспех инструмента или разрыв связи не доказывает, что запись отсутствует. Ошибки API выдаются без серверных тел/секретов; для разбора используйте штатную диагностику приложения.

Поддержан только [MCP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). Лимиты первой версии: один JSON-объект на строку, кадр до 2 МиБ, глубина JSON до 32, ответ API до 512 КиБ, HTTP-ожидание до 15 секунд, четыре одновременных обращения. Большая схема завершается явной ошибкой размера, не обрезанным графом. Постраничный контекст остаётся в TODO. Дубли ключей, некорректный UTF-8, небезопасные числовые request ID и пакеты JSON-RPC отвергаются с закрытием подключения; большие ID передавайте строками. JSON Schema 2020-12 проверяет форму входа, а сервер повторно проверяет домен, единицы и права.

Названия и параметры объектов — недоверенные данные. Их текст не расширяет разрешения агента. Внешний клиент отвечает за выбор провайдера и передачу ему контекста; Enersy не подключает модель автоматически.


### Исходные базисы p.u. — в разработке

Декларация формата v2 позволяет сохранять исходный базис вместе с коэффициентом:

```json
{
  "params": {"voltage_nom": "1.0000"},
  "parameterUnitDeclaration": {
    "formatVersion": 2,
    "units": {"voltage_nom": "p.u."},
    "bases": {
      "voltage_nom": {
        "profile": "ac-three-phase-rms-v1",
        "s_base_mva": 10,
        "v_base_kv": 110
      }
    }
  }
}
```

Это исходные 10 MVA трёхфазной мощности и 110 kV линейного RMS-напряжения,
отдельно от базиса исследования. MCP сохраняет коэффициент `1.0000`,
не переводит его в kV и не утверждает пригодность выбранной модели к расчёту.
Все три поля базиса обязательны. `null` вместо объекта базиса явно очищает
унаследованный базис; отсутствие ключа сохраняет его при той же единице p.u.

Повтор команды требует тех же UUID, ревизии, коэффициентов, единиц **и базисов**.
Изменение одного Sб/Uб под прежним UUID отклоняется. Если ответ не подтвердил
запрошенный базис точно, исход записи остаётся неопределённым: прочитайте схему
и явно повторите исходную команду. Основной стенд пока не обновлён.
