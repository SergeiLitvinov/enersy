# Запуск программы

Enersy сейчас объединяет редактор схем, каталог оборудования, API хранения и экспериментальный расчёт симметричного установившегося режима. Переходные процессы и подробные модели электрических машин ещё не реализованы.

## Требования

Установите Git и Docker с поддержкой Compose. На Windows включите Linux-контейнеры и запустите Docker Desktop. Порты 80, 3000, 5432, 8080 и 8001 должны быть свободны. Сборка впервые скачивает зависимости.

В каталоге проекта выполните:

```sh
docker compose up -d --build
```

Откройте [программу](http://localhost). Для обычной работы используйте этот адрес: через него доступны и интерфейс, и API. Прямой адрес frontend может не иметь тех же правил проксирования.

## Готовность и диагностика

```sh
docker compose ps
docker compose logs --tail 100 go-api julia-compute
```

[/health](http://localhost/health) сообщает о работе процесса, [/ready](http://localhost/ready) — о доступности БД после миграций. Реестр расчётов: [/api/ees/capabilities](http://localhost/api/ees/capabilities). Ошибка миграции блокирует готовность API; посмотрите журнал, прежде чем редактировать данные.

## Хранение данных

PostgreSQL хранит схемы в Docker-томе `postgres_data`. Чистую базу и существующую базу подготавливает API через версионированные миграции, включённые в его образ. Отдельный запуск `database/init.sql` при старте PostgreSQL больше не нужен. Существующий том сохраняется; не удаляйте его для исправления ошибки запуска.

Проверка здоровья контейнера API использует `/ready`. Слишком новая, неизвестная или незавершённая (`dirty`) версия базы блокирует готовность. Не исправляйте номер версии вручную: сохраните резервную копию и выясните причину по журналу. Подробнее — [обновление базы](../development/database).

Для остановки без удаления данных:

```sh
docker compose stop
```

Пароли в Compose — настройки локальной разработки. Подготовка публичного сервера, аутентификация и разграничение доступа требуют отдельной работы.

## Открыть документацию

Docker/Compose остаётся основным способом запуска приложения. Локальный Rust/Node из `C:\DevTools` нужен только разработчику; пользователь не обязан устанавливать компиляторы.

Автономная проверка экспериментальной Rust-библиотеки (она ещё не worker расчёта схем):

```sh
docker compose --profile numerics-check run --rm numerics-check
```

Контейнер читает исходники без записи в них; сборка остаётся в `/tmp`, тесты не требуют сети и не изменяют БД. Первый запуск скачивает официальный образ.

```sh
docker compose --profile docs up -d --build docs
```

Документация доступна по адресу `http://localhost:4173/`. Сборка создаёт справочник из исходников и проверяет внутренние ссылки. Подробнее — [процесс обновления](../development/documentation).
